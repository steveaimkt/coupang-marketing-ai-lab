# 데이터 분석 규칙

## 핵심 데이터 구조: `analysis` dict

`analyze_data()` 반환값. 모든 출력 모듈이 공유:
- `기간`, `월`, `다음월`, 기간 메타데이터
- `광고`, 총광고비, ROAS(전체매출/광고비), 일별/주간별/요일별 (광고 없으면 `사용: False`)
  - 광고 데이터: nca_daily_creative + pa_daily_keyword 날짜별 합산
- `광고운영`, 매출 성장 광고 보고서 기반 (광고 CSV 없을 때 대체)
- `판매`, 총매출, 평균전환율, 일별/주간별 집계
- `예상`, 일평균 × 해당월 일수 기반 월간 예상치 (매출, 광고비, ROAS, 주문, 방문자)
- `목표`, **이번달** 목표 (`--target-sales` 지정 시에만 생성)
  - 목표매출, 현재매출, 달성률, 잔여매출, 잔여일수, 목표일매출, 최근3일매출/평균
  - `광고전략`, 현재일평균광고비, 권장일광고비(남은 기간 하루 광고비 = 목표 일매출 ÷ 지금 ROAS), 매출증가필요율, 현재ROAS
  - ⚠️ **다음달** 목표는 여기가 아니라 `광고운영["목표"]` 에 있다 (아래 참조)
- `제품`, 상품별요약, 매출편중도, 취소현황, 아이템위너
- `교차분석`, 광고비↔매출 상관계수, 요일효율
- `키워드`, 상위 키워드, 지면별 성과 (선택)
- `제품트렌드`, 매출 급등/급락 TOP5, 판매량 상위/하위 5개, 판매 추세 변화 (±30%)
- `인사이트`, `필수확인`, `개선사항`, `운영플랜`, 룰 기반 자동 생성

## 제품 트렌드 분석 (필수)

`analyze_product_trends(kw_df, products)`, 모든 리포트에 반드시 포함:
- 판매량 상위/하위 5개: 제품별 데이터 기반
- 매출 급등/급락: 키워드 데이터의 최근 7일 vs 이전 기간 비교
- 판매 추세 변화: 주문 기준 30% 이상 증감 → 알림 대상

## 다음월 목표 계산 (일관성 필수)

**위치**: `analysis["광고운영"]["목표"]`, 최상위 `analysis["목표"]`(이번달)와 헷갈리기 쉽다.
매출 성장 광고 보고서가 있어 `광고운영["사용"] == True` 일 때만 생성된다.
필드: `목표ROAS`, `월매출`, `월광고비`, `월매출범위`, `월광고비범위`.

리포트의 "다음월(7월 등) 목표 매출"은 **여러 섹션에 등장하므로 반드시 한 기준으로 통일**한다.
어긋나면 "숫자가 안 맞는다"는 반복 클레임의 원인이 된다.

- **단일 진실원천**: `target["목표ROAS"] = max(300, 현재ROAS+50)`. 운영플랜 ROAS KPI도 이 값을 재사용 (별도 `ROAS+30` 공식 금지).
- **항등식 보장**: `월매출 = 월광고비 × 목표ROAS` 가 상·하한 모두 성립해야 함. 매출 범위를 광고비 범위와 독립 축소율(예: ×0.85)로 만들지 말 것.
- **사용자 명시 목표 우선**: 워크플로우 Step 2에서 받은 다음달 목표는 `--next-target-sales`로 전달 → 자동 "다음월 목표" 섹션도 그 값으로 고정(점값). 광고비 = 목표매출 ÷ 목표ROAS.
- 수동 3열표(광고 운영 요약)의 "다음달 목표" 열도 위 값과 동일하게 맞춘다.

## 인사이트 임계값

| 지표 | 기준 | 판정 |
|------|------|------|
| ROAS | < 200% | 적자 위험 |
| ROAS | 200~300% | 최적화 권장 |
| ROAS | >= 300% | 양호 |
| 구매전환율 | < 1.5% | 개선 필요 |
| 매출 편중 (1위) | > 70% | 위험 경고 |
| 취소율 | > 5% | 즉시 대응 |
| 상관계수 | < 0.2 | 연결 안됨 |
