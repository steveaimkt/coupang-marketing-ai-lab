# reference · 쿠팡 종합 리포트 에이전트 직접 운영하기

> SKILL.md 가 짧아야 지시를 잘 따른다. 자세한 것은 여기 둔다.

## 폴더 모양

받는 것은 zip 하나다. 수강생은 이름을 마음대로 정한 빈 폴더(예 `내리포트실습`)에 zip 을 압축을 풀지 않고 넣고, Code 탭에서 그 폴더를 연다.
시작 한 줄 · `이 폴더의 coupang-report-lab.zip 을 .claude/skills 에 풀고 쿠팡 리포트 에이전트 실습 시작`

시작할 때

```
{작업 폴더}/
└── coupang-report-lab.zip
```

Step 0 이 끝나면 (Step 2 · 3 에서 생기는 것까지)

```
{작업 폴더}/
├── CLAUDE.md                          Step 2 에서 생긴다 · 이 폴더의 기준
├── generate_report.py 외 5개          리포트 생성기 · 노션 발행기 · 메신저 발송기 · 로컬 웹(serve.py)
├── requirements.txt · .env.example    .env 로 복사해 키를 채운다
├── 진행상황.md                        어디까지 했는지
├── 리포트 자료/노을뷰티/2026-10-20/    1회차 샘플 4종 (10/01~10/20) · 읽기만
├── 보관/2026-11-09/                   2회차 샘플 4종 (10/21~11/09)
├── 결과물/                            만들 때마다 {자료 날짜}_{HHMM}/ 새 폴더 · 3회구동.md
├── coupang-report-lab.zip             그대로 둬도 된다
└── .claude/
    ├── skills/coupang-report-lab/     실습 스킬 (시작 한 줄로 풀린다)
    ├── skills/coupang-report/         단계형 스킬 (Step 3 에서 생긴다)
    ├── agents/리포트검토.md            검토 서브에이전트 (Step 3 에서 생긴다)
    ├── hooks/                         훅 3종 · 파일을 쓰거나 명령을 돌리기 전후에 저절로 도는 검사 (Step 3 새 세션부터 켜진다)
    ├── rules/                         코드 고칠 때 읽는 규칙
    └── settings.json                  훅 등록
```

Step 0 의 `install.py folders` 는 스킬 안 `assets/workspace/` 를 작업 폴더로 복사한다. 이미 있는 파일은 덮어쓰지 않는다. `--no-sample` 이면 `리포트 자료/` 를 비워 두고 `보관/` 을 넣지 않는다.

훅과 settings.json 은 세션을 새로 열어야 켜진다. 새 세션은 Step 3 에서 스킬을 넣은 뒤 한 번만 연다. 리포트는 Step 4 에서 처음 만들므로 훅이 켜진 상태로 만들어진다.

생성기(`generate_report.py` · `messenger.py`)는 결과물 폴더를, `data_loader.py` 는 CLAUDE.md 를 **자기 파일이 있는 폴더** 기준으로 찾는다. 작업 폴더 이름은 무엇이든 된다.

## 설치 점검 (Step 0)

`scripts/check_setup.py` 하나가 점검과 설치를 맡는다. 표준 라이브러리만 써서 부품이 하나도 없어도 돈다. 「이어서」 로 돌아왔을 때도 다시 돌린다.

| 점검 줄 | 어디에 쓰나 | 없으면 |
|---|---|---|
| python3 (3.9 이상) | 모든 명령 | 설치 명령을 보여 주고 묻는다. 맥 `brew install python` (Homebrew 가 없으면 설치 한 줄을 수강생이 터미널 앱에서 직접) · 윈도우 `winget install -e --id Python.Python.3.12` |
| pandas · numpy · openpyxl | 엑셀 읽기 · 계산 | `--install` 로 설치 |
| plotly | 리포트 차트 | `--install` 로 설치 |
| kaleido | 노션에 넣을 차트 그림 | `--install` 로 설치 |
| notion-client · requests | 노션 발행 (Step 6) | `--install` 로 설치 |
| 로컬 웹 서버 (http.server) | 리포트를 http://localhost 로 보기 | 파이썬에 들어 있다. 설치하지 않는다 |
| 크롬 브라우저 | 리포트 열어 보기 · kaleido 차트 그림 | 선택. 없어도 리포트는 나온다 |
| 노션 키 · 웹훅 (.env) | Step 6 · 7 | 설치가 아니다. 「나중에 · 선택」 으로만 보인다 |

`--install` 순서 · ① 지금 python3 에 `requirements.txt` 그대로 → ② 막히면 버전 고정 없이 → ③ 그래도 막히면 작업 폴더 안 `.venv` 를 만들어 그 안에 설치.
③ 으로 끝나면 「이 폴더는 .venv 를 씁니다」 가 나온다. 이 뒤 명령의 `python3` 를 `.venv/bin/python` 으로 바꾸고 `진행상황.md` 에 적는다. 훅은 표준 라이브러리만 써서 그대로 `python3` 로 돈다.

## 로컬 웹으로 보기

리포트는 file:// 이 아니라 로컬 웹 주소로 보여 준다. 작업 폴더의 `serve.py` 가 맡는다. 파이썬에 들어 있는 `http.server` 만 써서 따로 설치할 것이 없다.

| 명령 | 하는 일 |
|---|---|
| `python3 serve.py --latest` | 가장 최근 결과물 폴더의 리포트를 연다 |
| `python3 serve.py "결과물/{폴더}/{리포트}.html"` | 그 리포트를 연다 |
| `python3 serve.py` | 목록 `http://localhost:{포트}/` · 폴더를 나란히 본다 |
| `python3 serve.py --stop` | 서버를 끈다 |

- 뿌리는 `결과물/` 이다. 내 컴퓨터(127.0.0.1)에서만 열린다
- 포트는 8770 부터 빈 곳을 찾는다. 이미 떠 있으면 그 서버를 다시 쓰고 주소만 연다. 서버 정보는 `.serve.json` 에 둔다
- `generate_report.py` 는 `--no-open` 이 없으면 만든 리포트를 이 주소로 연다. 서버를 못 띄우면 file:// 로 대신 열고 그렇다고 알린다
- 리포트 html 은 차트 라이브러리(cdn.plot.ly)와 글꼴(Google Fonts)을 인터넷에서 받는다. 인터넷이 끊기면 차트가 비어 보인다
- 화면에는 늘 주소를 적는다 (예 `http://localhost:8770/2026-10-20_0702/노을뷰티_광고리포트_2026-10-20.html`)

## 보고 고치기 (Step 4-2)

기준은 `CLAUDE.md`, 모양은 `report_template.py`, 계산은 `data_loader.py` 에 산다. 4-2 는 모양만 고친다.

| 고르는 것 | report_template.py 에서 고치는 자리 |
|---|---|
| 1 색 · 글꼴 | 맨 위 컬러 팔레트(`C_PRIMARY` 등)와 머리 띠 `.report-header` 의 그라데이션 · `font-family` |
| 2 절 순서 | `generate_html_report()` 안에서 절(`<div class="section" id="...">`)을 이어 붙이는 순서 |
| 3 요약 카드 | 종합 요약(`summary`) 절의 카드 묶음 |
| 4 차트 모양 | `create_..._chart()` 함수들 (`go.Bar` · `go.Scatter` · 높이) |

고치기 전과 뒤는 목록 `http://localhost:{포트}/` 에서 두 폴더를 번갈아 열어 비교한다.

- 결과물 html 을 고치지 않는다. 다음 달 리포트에서 사라진다
- 고친 뒤 Step 4 와 같은 목표 숫자로 `generate_report.py` 를 다시 돌린다. 새 결과물 폴더에 나오고 앞 폴더는 남는다
- 리포트검토 서브에이전트로 매출 · 광고비 · ROAS 가 그대로인지 다시 센다
- 단계형 스킬 Step 5 「수정 대응」 과 다르다. 수정 대응은 이번 리포트 한 장의 내용을 HTML · 노션 페이지 · 노션 다운로드 파일 3곳에서 고친다
- 훅 · `guard_force_html` 은 결과물 html 을 Write 로 통째로 다시 쓰거나 `--notion --force-html` 일 때만 멈춘다. `report_template.py` 고치기와 다시 만들기는 막지 않는다
- 4-2 에서 다시 만들면 3회 구동 뒤 결과물 폴더가 4개가 된다 (2026-10-20 폴더 2개)

## 샘플 정답

가상 브랜드 「노을뷰티」. 실제 쿠팡 파일 4종을 고쳐 만들었다. 시트 · 칸 구성은 그대로이고, 브랜드 · 상품명 · 캠페인명 · 검색어는 가짜로 바꿨다. ROAS 는 **전체 매출 ÷ 광고비**.

| ㄴ 매출 성장 광고 · 신규 구매 고객 확보 광고 | 1,861,592원 · 2,262,147원 | 4,870,594원 · 6,185,919원 |

## 3회 구동

| 회차 | 무엇을 바꾸나 | 손댄 파일 | 샘플이면 |
|---|---|---|---|
| 1회차 | 아무것도 (1회차) | 없음 | 리포트와 검토 통과 |
| 2회차 | 자료만 · `보관/2026-11-09` 을 `리포트 자료/노을뷰티/` 로 | 없음 | 매출 26,433,740원 · 「주력 상품 매출 비중」 안내 (데일리 앰플 스틱 63.7%) |
| 3회차 | 기준만 · 매출 편중 70 → 50 | CLAUDE.md 한 줄 | 같은 63.7% 가 「매출 편중 위험」 경고로 바뀜 |

3회 구동을 마치면 `결과물/` 안에 폴더 3개가 쌓인다 (`2026-10-20_…` · `2026-11-09_…` · `2026-11-09_…`). 4-2 에서 다시 만들었으면 `2026-10-20_…` 이 하나 더 있어 4개다. 앞 회차 리포트는 덮어쓰지 않고 남는다. 3회차에 `--force-html` 은 쓰지 않는다.

3회차에 매출 편중 기준을 바꾸는 까닭 · 주문 변화 기준(30%)은 실제 자료에서 상품 여럿이 넘어, 기준을 바꿔도 리포트 화면(5개씩)에 차이가 잘 안 보인다.

2회차에 스킬 · CLAUDE.md · 코드는 하나도 고치지 않는다. 3회차에 고치는 것은 CLAUDE.md 「판단 기준」 한 줄뿐이다.

## 노션

노션 화면은 클로드가 열 수 없어 순서만 안내한다. 화면 이름은 버전에 따라 조금 다를 수 있다.

1. **통합 키** · 노션 설정 > 연결 > 통합 만들기 → 생긴 키를 복사한다
2. **페이지 ID** · 리포트를 올릴 노션 페이지 주소의 끝 32자리(영문과 숫자)를 복사한다. 주소 끝에 `?` 뒤 글자가 붙어 있으면 그 앞까지만 본다
3. **페이지 연결** · 그 페이지 오른쪽 위 ··· > 연결에서 방금 만든 통합을 허용한다. 이것을 빼면 키가 맞아도 올라가지 않는다
4. **.env 에 넣기** · `python3 .claude/skills/coupang-report-lab/scripts/open_webhook_setup.py --env` 로 `.env` 를 연다 (없으면 `.env.example` 로 만든다). `NOTION_API_KEY=` 뒤에 키, `NOTION_PAGE_ID=` 뒤에 32자리를 붙여 넣고 저장한다

그다음 단계형 스킬의 노션 배포 단계(스킬 화면의 Step 4)에서 「노션에 올려도 될까요?」 에 답한 뒤에만 올라간다.

통합 키는 비밀번호와 같다. 수강생이 `.env` 에 직접 붙여 넣는다. 채팅창으로 받지 않고, 받더라도 적지 않는다. 키는 화면에 띄우지 않는다.
`.env` 는 `guard_exfil` 훅(리포트 자료 · 결과물 · .env 가 밖으로 올라가려 하면 멈추는 훅)이 밖으로 못 나가게 막는다.

## 메신저

슬랙과 디스코드 모두 웹훅(채널에 글을 넣는 전용 주소)으로 보낸다. `messenger.py` 가 둘 다 맡는다. 화면 이름은 앱 판마다 조금 다를 수 있다.

**슬랙** · 워크스페이스 관리자 승인이 필요할 수 있다

1. api.slack.com/apps → Create New App
2. 「Create new app」 창에서 **Blank app** 을 고른다. **AI agent 가 미리 골라져 있으니 그대로 Continue 를 누르지 않는다.** (From scratch 는 이제 없다)
3. Continue → 4단계 설정 창. 앱 이름(예 노을뷰티 리포트)과 워크스페이스를 정하는 단계가 나오면 정한다. 「What it can respond to in Slack?」(Bot events · Workspace events) 단계는 **아무것도 넣지 않고 Continue**. Add Bot Events 는 누르지 않는다. 마지막 확인 단계는 기본값으로 넘어간다
4. 왼쪽 메뉴 Incoming Webhooks → Activate Incoming Webhooks 켜기 → Add New Webhook (to Workspace) → 채널 고르기 → Allow
5. Webhook URL(`https://hooks.slack.com/services/…`)을 복사해 `.env` 의 `SLACK_WEBHOOK_URL` 에 직접 붙여 넣는다

3 · 4단계 화면 이름은 버전에 따라 조금 다를 수 있다. AI agent 로 만들었으면 그 앱의 Incoming Webhooks 메뉴를 쓰고, 메뉴가 없으면 앱을 지우고 Blank app 으로 다시 만든다.

**디스코드** · 서버 관리 권한이 필요하다

1. 보낼 채널 옆 톱니(채널 편집)
2. 연동 → 웹후크 → 새 웹후크
3. 이름과 채널을 확인한다
4. 웹후크 URL(`https://discord.com/api/webhooks/…`)을 복사해 `.env` 의 `DISCORD_WEBHOOK_URL` 에 붙여 넣는다

**웹훅 주소는 비밀번호와 같다.** 아는 사람은 누구나 그 채널에 보낼 수 있다. 슬랙 주소는 `https://hooks.slack.com/services/…`, 디스코드 주소는 `https://discord.com/api/webhooks/…` 로 시작한다. 확인은 이 앞부분만으로 한다.

**.env** · `.env.example` 을 `.env` 로 복사하는 것은 클로드가 해도 된다. 주소는 수강생이 직접 붙여 넣는다. 채팅창에 붙여 넣지 않는다. 클로드는 주소를 받아 적지 않는다. `.env` 는 `guard_exfil` 훅이 밖으로 못 나가게 막는다. 하나만 채우는 것이 가장 헷갈리지 않는다.

**열어 주기** · `scripts/open_webhook_setup.py` 가 맡는다. 맥은 `open` · `open -e`, 윈도우는 기본 브라우저 · `notepad` 를 쓴다.

| 명령 | 하는 일 |
|---|---|
| `open_webhook_setup.py --slack` | 브라우저로 https://api.slack.com/apps 를 연다 |
| `open_webhook_setup.py --env` | `.env` 가 없으면 `.env.example` 로 만들고 텍스트 편집기로 연다 |
| `open_webhook_setup.py --check slack` · `--check discord` | 주소를 찍지 않고 「값이 들어 있음 · 꼴 맞음」 만 본다. 빈 값 · 앞뒤 공백 · 따옴표 · 가운데 공백 · 다른 쪽 주소를 잡는다 |
| `--dry-run` | 여는 명령만 보여 준다 |

디스코드는 채널 설정을 밖에서 열 수 없어 순서만 안내한다.

| 명령 | 하는 일 |
|---|---|
| `python3 messenger.py --test` | 「{브랜드} 리포트 연결 확인」 한 줄만 보낸다. 요약 전에 도착을 본다 |
| `python3 messenger.py --dry-run` | 요약 다섯 줄을 보여 주고 결과물 폴더에 `메신저요약.txt` 로 남긴다. 보내지 않는다 |
| `python3 messenger.py` | 요약을 보낸다. 「슬랙으로 보냅니다」 · 「디스코드로 보냅니다」 가 찍힌다 |
| `--to slack` · `--to discord` | `.env` 에 둘 다 있을 때 고른다. 없으면 슬랙으로 보내고 그렇다고 알린다 |

순서 · 시험 메시지를 보낼지 묻는다 → `--test` → 요약을 `--dry-run` 으로 보여 준다 → 「보낼까요?」 에 답을 받은 뒤 보낸다.

| 실패 메시지 | 뜻 | 대처 |
|---|---|---|
| 응답 404 · 401 · `invalid_webhook` · `Unknown Webhook` | 주소를 잘못 복사했거나 웹훅이 삭제됐다 | 웹훅을 다시 만들어 새로 붙여 넣는다 |
| 응답 403 | 권한이 없다 (주소가 틀려도 나올 수 있다) | 슬랙 관리자 승인 · 디스코드 서버 관리 권한 |
| 응답 400 | 형식이 맞지 않다 | 주소 끝이 잘렸는지, 슬랙과 디스코드 칸을 바꿔 넣지 않았는지 |
| 연결 안 됨 | 인터넷이 끊겼거나 주소 앞부분이 틀렸다 | 인터넷과 `https://hooks.slack.com/…` · `https://discord.com/api/webhooks/…` 를 확인 |
| 보냈다는데 채널에 없다 | 웹훅을 만들 때 다른 채널을 골랐다 | 웹훅 설정에서 채널을 확인한다 |
| 채팅에 웹훅 주소를 붙여 넣었다 | 주소가 대화 기록에 남았다 | 슬랙은 Incoming Webhooks 에서 그 웹훅을 Remove 후 새로 만들기 · 디스코드는 웹후크 삭제 후 새로 만들기 · 새 주소는 `.env` 에 직접 |

## 에러 대응

| 에러 | 무슨 뜻 | 어떻게 |
|---|---|---|
| `requirements.txt` · `generate_report.py` 가 없다 | Step 0 폴더 만들기를 건너뛰었다 | `python3 .claude/skills/coupang-report-lab/scripts/install.py folders` |
| `그대로 둠: …` | 같은 이름 파일이 이미 있다 | 고장이 아니다. 덮어쓰지 않았을 뿐이다. 새 원본이 필요하면 그 파일을 지우고 다시 돌린다 |
| `ModuleNotFoundError` | 파이썬 부품이 없다 | `python3 -m pip install -r requirements.txt` |
| `CLAUDE.md 가 없습니다` | 스킬부터 넣으려 했다 | `install.py claude-md` 를 먼저 |
| `CLAUDE.md 가 이미 있습니다` | Step 2 를 2번 했다 | 새로 만들지 않고 「판단 기준」 줄만 고친다 |
| `일별 판매 데이터(DAILY_SUMMARY_METRICS) 파일을 찾을 수 없습니다` | 날짜 폴더에 필수 파일이 없다 | 셀러 인사이트에서 받아 같은 폴더에 넣는다 |
| 「제품 트렌드」 가 비어 있다 | 매출 성장 광고 보고서가 7일치 이하다 | 8일 이상 받으면 나온다. 리포트는 그대로 쓸 수 있다 |
| 훅이 멈췄다 (`--force-html` · Write) | 사람이 손본 리포트 대신 새 리포트를 올리거나, 그 HTML 을 통째로 다시 쓰려 했다 | `--force-html` 을 빼거나 Edit 로 고친다. 꼭 필요하면 「손본 섹션이 빠지는데 진행할까요?」 를 사람에게 묻는다 |
| 훅이 멈췄다 (업로드) | 리포트 자료 · 결과물 · .env 가 밖으로 나가려 했다 | 올리지 않는다 |
| `결과물/ 에 리포트 폴더가 없습니다` | 리포트를 만들기 전에 메신저 요약을 돌렸다 | 리포트를 먼저 만들거나 `--data-dir` 로 자료 폴더를 지정한다 |
| 노션 PNG 차트가 빠졌다 | 차트 그림을 만드는 부품(kaleido)이 크롬을 못 찾았다 | 크롬을 설치하거나 HTML 다운로드 블록으로 본다 |
