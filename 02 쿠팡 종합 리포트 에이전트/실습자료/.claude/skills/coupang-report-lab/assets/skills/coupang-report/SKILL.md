# 쿠팡 광고 리포트 워크플로우

아래 6단계를 순서대로 실행합니다. 각 Step 완료 시 사용자 확인을 받고 다음으로 진행합니다.

## 변수 설정

사용자가 데이터 경로를 제공하면 아래 변수를 추출합니다:
- `{data_path}`: 데이터 폴더 경로 (예: `리포트 자료/노을뷰티/2026-10-20`)
- `{brand}`: 끝에서 두 번째 세그먼트 (예: `노을뷰티`)
- `{date_code}`: 마지막 세그먼트 (예: `2026-10-20`)
- `{date_display}`: date_code를 아래 규칙으로 변환 (예: `2026-10-20` → `2026-10-20`)
- `{report_title}`: `{brand} 광고 리포트 {date_display}` (예: `노을뷰티 광고 리포트 2026-10-20`)
- `{html_filename}`: `{brand}_광고리포트_{date_display}.html` (예: `노을뷰티_광고리포트_2026-10-20.html`)

### date_code 파싱 규칙

`generate_report.py`의 파일명 생성 로직과 **반드시 동일**해야 한다.
어긋나면 Step 4의 HTML 보호 모드가 다른 파일을 찾아 수동 섹션이 유실된다.

| date_code | 처리 | 예시 |
|-----------|------|------|
| 6자리 숫자 (YYMMDD) | `20YY.MM.DD` | `260323` → `2026.03.23` |
| 8자리 숫자 (YYYYMMDD) | `YYYY.MM.DD` | `20260323` → `2026.03.23` |
| `YYYY-MM-DD` 날짜 폴더 · 그 외 | **그대로 사용** | `2026-10-20` → `2026-10-20` |

> 이 실습의 날짜 폴더는 `2026-10-20` 꼴이다. "그대로 사용"으로 처리된다.

경로가 없으면 `리포트 자료/{브랜드}/` 안에서 이름이 가장 뒤인 날짜 폴더를 고르고, 그 경로를 보여 준 뒤 맞는지 묻습니다.

## Step 1. 데이터 분석 & 1차 리포트

1. 데이터 폴더의 파일 목록을 확인합니다:
   ```bash
   ls "{data_path}/"
   ```

   필수 2종이 있는지 확인합니다 (없으면 사용자에게 요청):
   - `*DAILY*SUMMARY*METRICS*.xlsx` (일별 판매)
   - `*VENDOR*ITEM*METRICS*.xlsx` (제품별 판매)

2. 1차 HTML 리포트를 생성합니다:
   ```bash
   python3 generate_report.py --data-dir "{data_path}" --report-title "{report_title}" --brand "{brand}" --no-open
   ```

### 결과 확인

1차 리포트 생성 후 핵심 수치를 사용자에게 요약 표시합니다:

```
--- Step 1/6 완료: 데이터 분석 ---
  브랜드: {brand}
  분석 기간: {기간} ({일수}일)
  총 매출: {총매출}
  총 광고비: {총광고비}
  ROAS: {ROAS}%
  인사이트: {N}건 / 필수확인: {N}건
```

### 사용자 확인

> 1차 분석 결과입니다. 확인 후 다음 단계로 진행하겠습니다.

---

## Step 2. 목표 & 마케팅 플랜 수집

### 사용자에게 질문

아래 3가지를 한 번에 질문합니다:

> Step 2로 진행합니다. 아래 정보를 알려주세요:
>
> 1. **이번 달 목표 매출**은 얼마인가요? (예: 7000만원, 1.5억), 없으면 "없음"
> 2. **마케팅 플랜이나 특이사항**이 있나요? (예: 광고비 증액 계획, 신제품 런칭, 프로모션 등), 없으면 "없음"
> 3. **다음 달 목표 매출**은 얼마인가요?, 없으면 "없음"

### 금액 파싱 규칙
- "7000만원" 또는 "7000만" → 70000000
- "1.5억" 또는 "1억5000만" → 150000000
- 숫자만 → 그대로 사용

### 사용자 응답 대기

응답을 받으면 Step 3로 진행합니다.

---

## Step 3. 최종 리포트 생성 & 수동 섹션 추가

### 실행

1. 목표 매출이 있으면 `--target-sales`(당월) + `--next-target-sales`(다음달) 포함하여 재생성합니다:
   ```bash
   python3 generate_report.py --data-dir "{data_path}" --report-title "{report_title}" --brand "{brand}" --target-sales {목표매출} --next-target-sales {다음달목표} --force-html
   ```
   > ⚠️ Step 2에서 받은 **다음달 목표를 반드시 `--next-target-sales`로 전달**한다. 빠뜨리면 자동 "다음월 목표" 섹션이 룰 기반 추정치를 써서 수동 섹션의 다음달 목표와 숫자가 어긋난다. (다음달 목표 "없음"이면 플래그 생략)
   >
   > ⚠️ `--brand`는 Step 1·4와 **동일하게** 전달한다. 생략해도 경로에서 추출되지만, 값이 갈리면 다른 파일명이 생성되어 Step 4의 HTML 보호가 무력화된다.

2. 생성된 HTML 파일에 아래 수동 섹션을 직접 추가합니다 (개선사항 섹션 앞에 삽입):

   **[목표 매출 달성 분석]**, `--target-sales`로 자동 생성되므로 수치 확인만
   - 이번달 목표 기준으로 달성률, 잔여 필요 매출, 목표 일매출, 권장 광고비 정확한지 확인

   **[광고 운영 요약 테이블]**, 자동 생성된 2열 테이블을 3열(구분 | 이번달 실적 | 다음달 목표)로 교체
   - 다음달 목표 매출 기준으로 광고비, 전환매출, ROAS, CTR, CVR 목표 산출
   - **다음달 목표 열의 매출/광고비/ROAS는 자동 "다음월 목표" 섹션과 동일 값으로 맞출 것** (월광고비 = 다음달목표 ÷ 목표ROAS)

   **[마케팅 플랜 섹션]**, 사용자가 제공한 마케팅 플랜 + 데이터 분석 기반으로 구성:
   - 제품별 매출 목표 테이블 (이번달 매출 | 다음달 목표 | 전략)
   - 리뷰 작업 등 마케팅 액션 테이블 (있는 경우)
   - 핵심 실행 플랜 (3~5개 항목)
   - 데이터 분석 요약 (최근 7일 추이, 매출 집중도, 광고 효율)

3. 브라우저에서 HTML을 열어 사용자에게 보여줍니다:
   ```bash
   open "output/{html_filename}"
   ```

### 사용자 확인

> Step 3/6 완료: 최종 리포트가 생성되었습니다. 브라우저에서 확인해주세요.
> 수정할 내용이 있으면 말씀해주세요. 확인되면 Notion 배포를 진행합니다.

수정 요청이 있으면 반영 후 재확인합니다.

### ⚠️ 중요: 수동 섹션 보호

이 단계 이후로는 `generate_report.py`를 `--force-html` 없이 실행해야 합니다.
`--notion`만 실행할 때는 기존 HTML을 덮어쓰지 않습니다.
수동 추가한 마케팅 플랜 등의 섹션이 날아가지 않도록 보호됩니다.

> 🛡️ `.claude/hooks/guard_force_html.py` 훅이 이를 강제합니다.
> 대상 HTML에 수동 섹션 마커(`마케팅 플랜`·`제품별 매출 목표`·`핵심 실행 플랜`·`다음달 목표`)가
> 있는 상태에서 `--force-html`을 실행하면 **명령이 차단**됩니다.
> 차단되면 임의로 우회하지 말고, 사용자에게 "수동 섹션이 초기화되는데 진행할까요?"를 먼저 확인하세요.

## Step 3.5. 리포트 검토 (배포 전 관문)

배포 전에 **`리포트검토` 서브에이전트**를 호출해 숫자를 독립 검증합니다.
만든 쪽이 자기 결과를 검토하면 자기 실수를 못 봅니다. 그래서 맥락을 끊고 따로 돌립니다.

```
Agent(subagent_type="리포트검토",
      prompt="데이터 폴더: {data_path} · 리포트 HTML: output/{html_filename}")
```

검토 서브에이전트는 **읽기 전용**입니다. 발견 목록만 돌려주고 파일은 건드리지 않습니다.

### 판정별 처리

| 판정 | 처리 |
|------|------|
| 통과 | 바로 Step 4 진행 |
| 조건부 통과 | [주의] 항목을 사용자에게 보여주고 반영 여부를 물은 뒤 진행 |
| 미통과 | **배포 중단.** [치명] 항목을 고치고 Step 3.5 재실행 |

수정은 검토 서브에이전트가 아니라 **메인 에이전트가** 합니다. 이 시점엔 아직 Notion에 안 올렸으므로
HTML 한 곳만 고치면 됩니다. (배포 후 수정은 Step 5의 3곳 동시 규칙을 따릅니다.)

### 사용자 확인

```
--- Step 3.5/6 완료: 검토 ---
  판정: {판정}
  발견: 치명 {N}건 / 주의 {N}건 / 참고 {N}건
```

> 검토 서브에이전트가 가장 먼저 보는 것은 **입력 파일 누락**입니다.
> `generate_report.py` 는 광고 파일 패턴이 안 맞아도 "없음 (선택사항)"으로 조용히 넘어가
> 광고 섹션이 통째로 빠진 리포트를 종료코드 0으로 내보냅니다. 겉보기엔 멀쩡합니다.

## Step 4. Notion + HTML 배포

### 실행

1. Notion에 업로드합니다 (`--notion --brand` 포함, HTML 보호):
   ```bash
   python3 generate_report.py --data-dir "{data_path}" --report-title "{report_title}" --target-sales {목표매출} --next-target-sales {다음달목표} --brand "{brand}" --notion --no-open
   ```
   - Notion 구조: `광고 리포트 에이전트 > {brand} > {report_title}`
   - 기존 동일 제목 페이지는 자동 아카이브
   - **`--force-html` 없이 실행** → 수동 추가 섹션이 포함된 HTML 유지

2. Notion 페이지 상단(요약 callout 바로 뒤)에 HTML 다운로드 블록을 추가합니다:
   - Notion File Upload API로 HTML 파일 업로드: POST /v1/file_uploads → POST .../send (multipart)
   - 파일명: `{html_filename}` (예: `노을뷰티_광고리포트_2026-10-20.html`)
   - 📥 callout + file 블록을 요약 callout 바로 뒤에 배치 (after 파라미터 사용)

3. Notion 페이지에도 수동 섹션 내용을 반영합니다:
   - 광고 운영 요약 테이블 → 3열로 교체 (기존 삭제 후 새 테이블 생성)
   - 마케팅 플랜 섹션 → 개선사항 앞에 추가 (heading + table + numbered_list)
   - 목표 매출 달성 분석 → 당월 예상 실적 테이블에 목표 대비 분석 반영

### 에러 처리
- Notion 실패 → 경고 후 계속 (HTML은 유지)

### 사용자 확인

```
--- Step 4/6 완료: 배포 ---
  HTML: output/{html_filename}
  Notion: {notion_url}
  HTML 다운로드: Notion 페이지 상단에서 가능
```

## Step 5. 리포트 수정 대응

### 수정 요청 시 3곳 동시 수정 (필수)

사용자가 리포트 내용 수정을 요청하면 반드시 아래 3곳을 한 번에 수정합니다:

1. **로컬 HTML** (`output/{html_filename}`), Edit 도구로 직접 수정
2. **Notion 페이지**, Notion API로 해당 블록 수정
   - 테이블 열 수 변경 시: 기존 테이블 삭제 → 새 테이블 생성
   - 텍스트 수정: PATCH /v1/blocks/{block_id}
3. **Notion 다운로드 HTML**, 수정된 HTML 파일로 교체
   - 기존 file 블록 삭제 → File Upload API로 새 파일 업로드 → callout 뒤에 추가

### 수정 완료 보고

```
3곳 모두 수정 완료:
  - HTML: 수정 완료
  - Notion 페이지: 수정 완료
  - Notion 다운로드 파일: 교체 완료
```

## Step 6. 메신저 요약 (복사용 + 채널 발송)

### 실행

리포트 완료 후 아래 형식으로 요약을 작성하여 사용자에게 전달합니다.
사용자가 메신저(카톡, 슬랙 등)에 바로 복사하여 보고할 수 있는 형태입니다.

### 요약 형식 (카톡 공유용)

```
[{brand}] {월} 광고 리포트 ({분석기간})

▸ 매출 {총매출} / 광고비 {총광고비}
▸ ROAS {ROAS}% / 주문 {총주문}건 / 전환율 {전환율}%

▸ 목표 {목표매출} 대비 {달성률}% 달성
▸ 예상 매출 {예상매출} ({해당월일수}일 환산)

▸ 매출 TOP 3
  1) {1위 상품명}, {매출}
  2) {2위 상품명}, {매출}
  3) {3위 상품명}, {매출}

▸ 쿠팡 매출 플랜
  - {마케팅 플랜 핵심 항목 2~3개}
  - {필수 확인사항 중 긴급 항목 1개}

▸ {다음월} 목표: {다음달목표}

📎 {notion_url}
```

### 규칙
- 금액은 만원 단위 (4,369만원)
- 상품명은 전체 표시
- 목표/다음달 목표 없으면 해당 줄 생략
- Notion URL 항상 포함

### 채널로 보내기 (사람 승인 뒤)

1. 먼저 보낼 내용을 보여 준다. 보내지 않는다:
   ```bash
   python3 messenger.py --data-dir "{data_path}" --link "{notion_url}" --dry-run
   ```
2. **「이 내용으로 팀 채널에 보낼까요?」** 라고 묻고 멈춘다. 답을 받기 전에는 보내지 않는다.
3. 승인하면 보낸다. 웹훅 주소는 `.env` 의 `SLACK_WEBHOOK_URL` 또는 `DISCORD_WEBHOOK_URL` 이다:
   ```bash
   python3 messenger.py --data-dir "{data_path}" --link "{notion_url}"
   ```
4. `.env` 에 웹훅이 없으면 위 요약 형식을 복사용으로만 주고 끝낸다.

## 제품 트렌드 분석 (리포트 내 포함)

리포트 생성 시 아래 제품 분석을 자동 수행하여 리포트에 포함합니다.
데이터가 7일 이상일 때 최근 7일 vs 이전 기간 비교로 분석합니다.

### 매출 급등/급락 제품
- **최근 7일 매출 급등 제품**: 이전 기간 대비 매출이 크게 증가한 제품 TOP 5
- **최근 7일 매출 급락 제품**: 이전 기간 대비 매출이 크게 감소한 제품 TOP 5

### 판매량 상위/하위 제품
- **판매량 상위 5개 제품**: 전체 기간 기준 판매량 TOP 5 (매출, 전환율 포함)
- **판매량 하위 5개 제품**: 매출 발생 제품 중 판매량 하위 5개 (개선 필요 제품)

### 판매 추세 변화 제품 (알림 대상)
- **판매량 증가 추세 제품**: 최근 7일 광고 주문이 이전 대비 CLAUDE.md 「판단 기준」 의 주문변화_기준_pct (기본 30%) 이상 증가 → 프로모션 확대 검토
- **판매량 감소 추세 제품**: 최근 7일 광고 주문이 이전 대비 같은 기준 (기본 30%) 이상 감소 → 원인 파악 필요

분석 결과는 리포트의 "제품 트렌드" 섹션에 표시하고, 급등/급락 제품은 Step 6 메신저 요약에도 반영합니다. 요약에는 변화가 큰 3개만 보이고 나머지는 「외 N개」 로 줄입니다.

## 참고사항

- ROAS 계산: 전체 매출 / 총 광고비 (광고매출 기준 아님)
- 광고 데이터: nca_daily_creative + pa_daily_keyword 날짜별 합산 (날짜가 int형 YYYYMMDD일 수 있음)
- HTML 파일명: `{brand}_광고리포트_{date_display}.html` (Notion 다운로드용)
- Notion 루트 페이지: `305d6f058339803f9795c65914019b06`
- 에러 격리 원칙: Notion 실패해도 HTML은 항상 생성
- 제품명: 전체 표시 (말줄임 금지)
- HTML 보호: `--notion`만 실행 시 기존 HTML 덮어쓰지 않음 (`--force-html`로 강제 재생성)
- 수정 시 3곳 동시: HTML + Notion 페이지 + Notion 다운로드 파일 항상 함께 수정

## 호출 트리거 & 트러블슈팅

이 워크플로우는 **"광고 리포트 작성하자"** 라고 말하면 실행됩니다.
아래 표현도 동일하게 매칭됩니다:

```
"광고 리포트 작성하자"     ← 기본 트리거
"광고 리포트 작성"
"리포트 작성해줘"
"리포트 시작"
"리포트 자료/노을뷰티/2026-11-09 리포트 만들어줘"   ← 경로까지 한 번에 지정
```

슬래시 명령어로는 `/광고리포트작성` 으로도 호출할 수 있습니다.

워크플로우가 실행되지 않을 때 아래를 확인합니다.

### 1. SKILL.md 파일 위치 확인

```
프로젝트 루트/.claude/skills/광고리포트작성/SKILL.md
```

반드시 `.claude/skills/광고리포트작성/` 폴더 안에 `SKILL.md` 파일이 있어야 합니다.

```bash
# 확인
ls .claude/skills/광고리포트작성/SKILL.md
```

### 2. SKILL.md frontmatter 확인

파일 최상단에 아래 형식의 frontmatter가 있어야 합니다:

```yaml
---
name: coupang-report
description: "설명 텍스트"
---
```

- `name`: 스킬 이름 (폴더명과 반드시 일치. 슬래시 명령어 `/광고리포트작성`이 됨)
- `description`: 트리거 조건 설명 (이 텍스트의 키워드로 자연어 자동 매칭)
- frontmatter가 없거나 형식이 틀리면 스킬이 등록되지 않음

### 3. Claude Code 재시작

SKILL.md를 새로 만들거나 수정한 경우, Claude Code를 재시작해야 반영됩니다:

```bash
# 터미널에서 Claude Code 재시작
claude

# 또는 VS Code에서: Cmd+Shift+P → "Claude: Restart"
```

### 4. 프로젝트 루트 확인

Claude Code가 실행되는 작업 디렉토리가 프로젝트 루트인지 확인합니다:

```bash
# 현재 디렉토리 확인, generate_report.py 가 보이면 프로젝트 루트
pwd && ls generate_report.py
```

다른 디렉토리에서 Claude Code를 실행하면 `.claude/skills/` 폴더를 찾지 못합니다.
이 스킬의 모든 bash 명령은 **실습자료/ 폴더에서 실행**되는 것을 전제로 합니다 (`python3` 로 실행).

### 5. 그래도 안 될 때

스킬 없이도 Step 1은 직접 실행할 수 있습니다:

```bash
python3 generate_report.py --data-dir "{data_path}" --brand "{brand}" --no-open
```

이후 Step 2~6은 이 문서를 참고해 수동으로 진행합니다.
