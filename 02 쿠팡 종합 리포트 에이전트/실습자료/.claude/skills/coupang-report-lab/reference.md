## 왜 CLAUDE.md 가 먼저인가

| 순서 | 부품 | 없으면 |
|---|---|---|
| 1 | CLAUDE.md | 스킬과 에이전트가 각자 다른 기준으로 센다 |
| 2 | coupang-report 스킬 | 매주 같은 순서를 손으로 다시 시킨다 |
| 3 | 리포트검토 서브에이전트 | 만든 쪽 실수를 아무도 못 잡는다 |

설치 도구(`install.py skill-agent`)는 CLAUDE.md 가 없으면 멈춘다. 순서를 지키게 하려는 것이다.

## 샘플 정답

가상 브랜드 「노을뷰티」. 실제 쿠팡 파일 4종을 고쳐 만들었다. 시트 · 칸 구성은 그대로이고, 브랜드 · 상품명 · 캠페인명 · 검색어는 가짜로 바꿨다. ROAS 는 **전체 매출 ÷ 광고비**.

| 파일 (받은 이름 그대로) | 쿠팡 메뉴 |
|---|---|
| `A0000…_pa_daily_keyword_….xlsx` | 광고센터 > 광고 보고서 > **매출 성장 광고 보고서** (키워드 단위) |
| `A0000…_nca_daily_creative_….xlsx` | 광고센터 > 광고 보고서 > **신규 구매 고객 확보 광고 보고서** |
| `SELLER_INSIGHTS_DAILY_SUMMARY_METRICS_(0).xlsx` | 셀러 인사이트 > 일별 판매 (맨 아래 합계 행 1개) |
| `SELLER_INSIGHTS_VENDOR_ITEM_METRICS_(0).xlsx` | 셀러 인사이트 > 상품별 판매 |

| | 1회차 `2026-10-20` | 2회차 `2026-11-09` |
|---|---|---|
| 기간 | 2026.10.01 ~ 2026.10.20 | 2026.10.21 ~ 2026.11.09 |
| 매출 | 7,892,080원 | 22,900,440원 |
| 광고비 (매출 성장 + 신규 구매 고객 확보) | 4,000,690원 | 10,575,310원 |
| ㄴ 매출 성장 광고 · 신규 구매 고객 확보 광고 | 1,793,660원 · 2,207,030원 | 4,667,890원 · 5,907,420원 |
| ROAS (전체 매출 기준) | 197.3% | 216.5% |
| 매출 1위 | 두피 케어 샴푸 24.7% | PDRN 앰플 1.5ml*30개입 59.5% |
| 편중 인사이트 (기준 70%) | 없음 | 「주력 상품 매출 비중」 (안내) |
| 편중 인사이트 (기준 50%) | 없음 | 「매출 편중 위험」 (경고) |
| 주문 30% 넘게 변한 상품 | 10개 (탄력 앰플 마스크 +167% 등) | 10개 (딥 윤광 슬리핑팩 +112% 등) |
| 합계 행까지 더하면 | 15,784,160원 (틀림 · 정확히 2배) | 45,800,880원 (틀림 · 정확히 2배) |

주문 변화는 매출 성장 광고 보고서 안에서 최근 7일과 그 앞 13일(7일로 환산)을 비교한다.
실제 자료라 주문이 30% 넘게 변한 상품이 많다. 리포트는 늘어난 쪽과 줄어든 쪽을 5개씩 보여 주고, 메신저 요약은 변화가 큰 3개만 보이고 나머지는 「외 N개」 로 줄인다.

## 3회 구동

| 회차 | 무엇을 바꾸나 | 손댄 파일 | 샘플이면 |
|---|---|---|---|
| 1회차 | 아무것도 (1회차) | 없음 | 리포트와 검토 통과 |
| 2회차 | 자료만 · `보관/2026-11-09` 을 `리포트 자료/노을뷰티/` 로 | 없음 | 매출 22,900,440원 · 「주력 상품 매출 비중」 안내 (PDRN 앰플 59.5%) |
| 3회차 | 기준만 · 매출 편중 70 → 50 | CLAUDE.md 한 줄 | 같은 59.5% 가 「매출 편중 위험」 경고로 바뀜 |

3회 구동을 마치면 `결과물/` 안에 폴더 3개가 쌓인다 (`2026-10-20_…` · `2026-11-09_…` · `2026-11-09_…`). 앞 회차 리포트는 덮어쓰지 않고 남는다. 3회차에 `--force-html` 은 쓰지 않는다.

3회차에 매출 편중 기준을 바꾸는 까닭 · 주문 변화 기준(30%)은 실제 자료에서 상품 여럿이 넘어, 기준을 바꿔도 리포트 화면(5개씩)에 차이가 잘 안 보인다.

2회차에 스킬 · CLAUDE.md · 코드는 하나도 고치지 않는다. 3회차에 고치는 것은 CLAUDE.md 「판단 기준」 한 줄뿐이다.

## 노션

1. 노션 설정 > 연결 > 통합 만들기 → 키를 받는다
2. `.env.example` 을 `.env` 로 복사하고 `NOTION_API_KEY` 와 리포트를 올릴 페이지의 `NOTION_PAGE_ID` 를 넣는다
3. 그 노션 페이지 오른쪽 위 ··· > 연결에서 방금 만든 통합을 허용한다
4. 단계형 스킬 Step 4 · 「노션에 올려도 될까요?」 에 답한 뒤에만 올라간다

키는 화면에 띄우지 않는다. `.env` 는 `guard_exfil` 훅이 밖으로 못 나가게 막는다.

## 메신저

- 슬랙 · 채널 설정 > 연동 > 앱 추가 > Incoming Webhook 주소를 `.env` 의 `SLACK_WEBHOOK_URL` 에
- 디스코드 · 채널 설정 > 연동 > 웹후크 만들기 > 주소 복사를 `.env` 의 `DISCORD_WEBHOOK_URL` 에
- 먼저 `--dry-run` 으로 다섯 줄을 보여 주고, 「보낼까요?」 에 답을 받은 뒤 보낸다

## 에러 대응

| 에러 | 무슨 뜻 | 어떻게 |
|---|---|---|
| `ModuleNotFoundError` | 파이썬 부품이 없다 | `python3 -m pip install -r requirements.txt` |
| `CLAUDE.md 가 없습니다` | 스킬부터 넣으려 했다 | `install.py claude-md` 를 먼저 |
| `CLAUDE.md 가 이미 있습니다` | Step 2 를 두 번 했다 | 새로 만들지 않고 「판단 기준」 줄만 고친다 |
| `일별 판매 데이터(DAILY_SUMMARY_METRICS) 파일을 찾을 수 없습니다` | 날짜 폴더에 필수 파일이 없다 | 셀러 인사이트에서 받아 같은 폴더에 넣는다 |
| 「제품 트렌드」 가 비어 있다 | 매출 성장 광고 보고서가 7일치 이하다 | 8일 이상 받으면 나온다. 리포트는 그대로 쓸 수 있다 |
| 훅이 멈췄다 (`--force-html` · Write) | 사람이 손본 리포트 대신 새 리포트를 올리거나, 그 HTML 을 통째로 다시 쓰려 했다 | `--force-html` 을 빼거나 Edit 로 고친다. 꼭 필요하면 「손본 섹션이 빠지는데 진행할까요?」 를 사람에게 묻는다 |
| 훅이 멈췄다 (업로드) | 리포트 자료 · 결과물 · .env 가 밖으로 나가려 했다 | 올리지 않는다 |
| `결과물/ 에 리포트 폴더가 없습니다` | 리포트를 만들기 전에 메신저 요약을 돌렸다 | 리포트를 먼저 만들거나 `--data-dir` 로 자료 폴더를 지정한다 |
| 노션 PNG 차트가 빠졌다 | 차트 그림을 만드는 부품(kaleido)이 크롬을 못 찾았다 | 크롬을 설치하거나 HTML 다운로드 블록으로 본다 |
