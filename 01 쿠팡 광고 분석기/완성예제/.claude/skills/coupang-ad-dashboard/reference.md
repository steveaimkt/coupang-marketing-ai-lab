# 쿠팡 광고 대시보드 제작 규격

## 적용 범위

이 문서만으로 대시보드를 처음부터 만들 수 있어야 한다. 다른 프로젝트의 코드를 열어 볼 수 있더라도 고정 증감률·목업 데이터·상충하는 분류 기준·단정적인 운영 권고는 복사하지 않는다. 전환매출은 광고 전환매출로 표기하며 사업 전체 매출이나 순이익으로 표현하지 않는다.

## 결과물과 실행 방식

기본 static 결과:

```text
결과물/2026-10-20_1405/   만들 때마다 새 폴더 · {자료 날짜}_{만든 시각 HHMM}
├── index.html       6개 탭과 접근 가능한 화면 구조
├── styles.css       반응형 레이아웃과 인쇄 스타일
├── script.js        실제 집계 데이터, 탭·검색·정렬·차트 동작
└── 검증결과.md      원본/설정/합계 대조/작동 확인/미확인 항목
```

- 결과물 뿌리는 작업 폴더의 `결과물/` 이다 (`output_directory: 결과물`). 만들 때마다 그 안에 새 폴더를 만들고, 지난 폴더는 덮어쓰지 않는다.
- 폴더 이름의 자료 날짜는 읽은 데이터 날짜 폴더 이름(예 `2026-10-20`), 시각은 이 컴퓨터의 현지 시각이다. 같은 이름이 있으면 `_2`, `_3` 을 붙인다.
- 가장 최근 결과물은 `결과물/` 안 폴더 이름순 마지막이다. 원본 대조, 브라우저 확인, 배포는 따로 말이 없으면 이 폴더를 쓴다.

- 클로드 코드가 업로드되거나 경로로 지정된 `.xlsx` 또는 `.csv`를 사용 가능한 읽기 도구로 분석한다. 웹 페이지가 업로드 임시 경로나 로컬 절대 경로의 원본을 직접 읽도록 만들지 않는다.
- static은 파일을 직접 열어도 동작하도록 필요한 데이터를 안전하게 내장한다. 런타임 fetch와 CDN에 의존하지 않고 차트는 SVG/canvas 등으로 구현할 수 있다. 문자열은 HTML로 실행되지 않게 처리한다.
- 새 입력 파일은 클로드 코드 대화에 다시 업로드하거나 경로를 지정한 뒤 스킬 재실행으로 반영한다. 클로드 코드에 원본을 제공하는 단계와 완성된 웹 화면의 업로드 기능을 구분하고, static에서 작동하지 않는 업로드 버튼을 만들지 않는다.
- webapp은 기존 기술 구성을 존중한다. 필요하면 참고 구조처럼 화면 컴포넌트와 분석 모듈을 분리하고 설치·실행 방법을 제공한다. 원본을 브라우저에서 파싱하는 경우 외부 전송 없이 처리한다. 실제 처리 방식과 다른 개인정보 안내를 넣지 않는다.
- 인쇄/PDF 저장은 선택 기능이다. 제공한다면 인쇄 대상 범위를 명확히 하고 표와 차트 잘림을 확인한다.

## 공통 화면

밝은 회색 배경 위 흰 카드, 파랑/인디고 강조색, 얇은 테두리와 절제된 그림자를 사용한다. 상단에 제목, 실제 분석 기간, 원본 파일명, 전환 기준을 보여 준다. 데스크톱은 상단 탭, 모바일은 가로로 넘기는 탭 또는 접근 가능한 메뉴를 쓴다.

표는 표 영역 안에서 가로 스크롤을 허용하되 페이지 전체가 넘치지 않게 한다. 키보드로 탭과 버튼을 사용할 수 있고 선택 상태가 구분되어야 한다. 금액은 원, 횟수는 건/회, 비율은 %로 표시한다.

## 필수 6개 탭

| 탭 | 필수 내용 | 작동 기준 |
|---|---|---|
| 대시보드 | 요약 문장, 광고비·광고 전환매출·ROAS·주문수·CTR·CPC·CVR·CPA 카드, 일별 광고비/매출 차트, 캠페인 ROAS TOP 5와 성과표 | 모든 수치가 같은 집계 범위에서 나오며 순위에 광고비와 주문수도 확인 가능 |
| 일별 | 날짜순 광고비/매출/ROAS 추이, 노출→클릭→주문 단계별 수치와 비율, 일별 상세 표 | 금액과 ROAS 축/단위를 분리하고 결측 날짜를 임의의 0으로 채우지 않음 |
| 지면 | 원본에 있는 검색/비검색/기타 지면의 광고비·매출·ROAS·광고비 비중, 지면별 캠페인 성과 | 없는 지면을 만들지 않으며 지면 합계가 전체와 일치 |
| 키워드 | 분류별 건수, 전체/주문발생/효자/낭비검토 필터, 검색창, 성과표 | 검색과 필터가 함께 적용되고 숫자는 숫자순, 문자열은 문자열순으로 양방향 정렬; 페이지 이동 또는 더 보기로 전체 결과 접근 |
| 인사이트 | 전체 요약, 주문 없는 지출, 고효율 키워드, 지면 비교, 클릭 대비 주문 검토 | 각 문장에 대상·기간·근거 수치가 연결되고 해당 데이터가 없으면 없다고 표시 |
| 실행 계획 | 긴급/이번 주/이번 달로 나눈 제안, 대상·근거·할 일·재확인 지표 | 인사이트와 동일한 분류 사용; 광고 중지나 증액을 실행했다고 표현하지 않음 |

캠페인·키워드 표에는 최소한 식별 정보, 광고비, 클릭, 주문, 전환매출, ROAS, CVR을 둔다. 필터 결과 0건, 데이터 없음, 계산 불가를 정상 상태로 처리한다. 목표가 설정된 경우에만 목표 대비 결과를 보여 준다. 비교 기간 데이터가 없으면 증감률을 생략한다. 전월 대비나 월간 절감액을 임의로 만들지 않는다.

## 입력 열과 데이터 정리

기본 샘플은 UTF-8 BOM이 포함된 CSV이며 헤더 1행과 데이터 1,897행으로 구성된다. CSV를 실제로 열어 인코딩과 구분자, 헤더 수, 데이터 행 수를 확인한다. 워크시트 개념을 전제로 하지 않는다. `.xlsx`가 별도로 업로드된 경우에만 실제 시트도 확인한다.

| 의미 | 실제 열 |
|---|---|
| 날짜 | 날짜 |
| 캠페인 식별 | 캠페인 ID, 캠페인명 |
| 광고그룹 | 광고그룹 (`광고그룹명`은 명시적으로 지원하는 별칭) |
| 광고 상품 | 광고집행 상품명, 광고집행 옵션ID |
| 전환 상품 | 광고전환매출발생 상품명, 광고전환매출발생 옵션ID |
| 지면/키워드 | 광고 노출 지면, 키워드 |
| 기본 성과 | 노출수, 클릭수, 광고비 |
| 1일 전환 | 총 주문수(1일), 총 전환매출액(1일) |
| 14일 전환 | 총 주문수(14일), 총 전환매출액(14일) |

- 필수 열은 날짜, 캠페인 ID/명, 지면, 키워드, 기본 성과와 선택한 전환 기준의 주문/매출이다. 필수 열이 없으면 열 이름을 알려 주고 수치를 생성하지 않는다.
- 날짜의 YYYYMMDD 숫자/문자열을 날짜로 검증·변환한다. 다른 형식은 실제 셀 타입을 확인해 처리한다. 식별자는 숫자 연산 대상이 아닌 문자열로 보존한다.
- 금액/횟수의 숫자와 쉼표 문자열을 구분해 파싱한다. 비어 있거나 잘못된 값을 무조건 0으로 바꾸지 않는다. 제외 또는 보류한 행 수·이유를 검증 기록에 남긴다.
- 원본의 클릭률 및 문자열 ROAS를 평균 내지 않고 기초 합계로 다시 계산한다.
- 총 주문수와 판매수량은 다르다. CVR·CPA에는 주문수를 사용한다. 총 전환매출에 직접/간접 매출을 다시 더하지 않는다.
- 캠페인은 ID로 묶고 이름을 표시한다. 키워드 기본 집계 키는 캠페인 ID + 광고그룹 + 지면 + 키워드이다. 같은 검색어의 다른 캠페인을 합쳐 운영 제안을 만들지 않는다.
- 키워드가 `-`/빈칸인 행은 키워드 미지정으로 구분하고 효자/낭비 키워드 추천에서 제외한다. 전체·일별·캠페인·지면 집계에는 포함한다.
- 동일 날짜/키워드라도 광고 상품과 전환 상품이 다를 수 있다. 중복이라고 임의 삭제하지 않는다. 합계 행이 있으면 근거를 확인해 상세 행과 이중 집계하지 않는다.

## 계산식

선택된 기간과 전환 기준으로 노출·클릭·광고비·주문·전환매출을 먼저 합산한 뒤 비율을 계산한다. 전체/일별/캠페인/지면/키워드 모두 같은 함수를 사용한다.

| 지표 | 계산 |
|---|---|
| CTR (%) | 클릭 ÷ 노출 × 100 |
| CPC (원) | 광고비 ÷ 클릭 |
| CVR (%) | 주문 ÷ 클릭 × 100 |
| ROAS (%) | 전환매출 ÷ 광고비 × 100 |
| CPA (원) | 광고비 ÷ 주문 |

분모가 0이면 null로 보존하고 화면에는 `계산 불가`로 표시한다. 분모가 양수이고 분자가 0인 0%와 구분한다. 반올림은 표시 단계에만 적용한다. 기간 비교도 기간별 합계로 다시 계산한다.

## 키워드 분류: 하나의 공통 규칙

아래 순서로 겹치지 않게 분류하며 카드·필터·인사이트·실행 계획이 같은 결과를 사용한다.

1. 키워드 미지정: `-` 또는 빈 키워드. 추천 대상 제외.
2. 효자: 계산 가능한 ROAS가 `star_roas_pct` 이상이고 주문이 `minimum_orders_for_star` 이상.
3. 낭비 검토: 광고비가 `waste_cost_krw` 이상이고 주문이 0.
4. 가능성 검토: 주문이 있고 계산 가능한 ROAS가 `potential_roas_pct` 미만.
5. 주문 발생: 나머지 주문이 있는 항목.
6. 관찰: 주문이 없고 광고비 또는 클릭이 있는 항목.
7. 활동 없음: 나머지 항목.

이 분류는 설정된 관찰 기준이며 수익성 확정 판정이 아니다. 미지정 목표를 300%로 대체하지 않는다. 검토 제안은 근거 수치를 제공하고 마진·재고·전환 집계 시점 등 확인이 필요한 조건을 짧게 적는다. 14일 기준 최근 날짜의 전환 확정 여부를 파일명만으로 단정하지 않는다. 미래 매출 증가나 절감액을 보장하지 않는다.

## 성공 확인표

| 확인 | 통과 조건 |
|---|---|
| 원본 | 업로드된 실제 파일/인코딩/기간/행 수/전환 기준 기록, 원본 보존 |
| 합계 | 원본 유효 행에서 별도로 합산한 광고비·매출·주문과 화면 집계 일치 |
| 분해 | 일별·캠페인별·지면별 합계가 전체와 일치; 키워드 미지정 포함 전체 키워드 집계도 일치 |
| 비율 | 집계값으로 재계산한 ROAS·CTR·CPC·CVR·CPA와 일치; 0 분모 구분 |
| 표본 | 실제 캠페인 1개와 키워드 집계 키 1개의 원본 행을 추적해 검산 |
| 탭 | 6개 모두 실제 내용 표시, 탭 이동 시 오류 없음 |
| 검색/정렬 | 부분 검색·분류 결합·숫자/문자 양방향 정렬·0건·전체 결과 접근 확인 |
| 화면 | 데스크톱과 390px 너비에서 카드/차트/표 확인; 페이지 전체 가로 넘침 없음 |
| 오류 | 실행 후 브라우저 콘솔 오류 확인; 도구가 없으면 미확인 기록 |
| 반복 | 같은 입력/설정은 같은 합계; 전환 기준 변경 시 모든 탭 반영 |

금액 비교는 원본 정밀도 기준으로 하며 부동소수점 오차 허용치는 0.01원 이내, 횟수는 정확히 일치시킨다. 검증 기록에는 실행한 확인과 미확인을 구분한다. 스킬 파일 생성만으로 대시보드가 완성됐다고 보고하지 않는다.

## 완성 화면 안내와 수정

사용자에게 현재 과정의 목적, 읽거나 수정하는 문서의 역할, 실제 변경 내용과 확인 결과를 채팅으로 설명한다. `SKILL.md`는 업무 순서, `config.md`는 다음 실행에 쓸 설정, `reference.md`는 계산·화면의 세부 규칙이다. 결과물 파일은 이번 구현에 맞춰 구조/표현/동작/검증 기록의 역할을 안내한다.

완성 화면을 열어 원본·기간·전환 기준, KPI, 차트, 상세 표, 각 메뉴에서 읽을 수 있는 내용을 실제 결과와 연결해 안내한다. 화면을 보지 못하면 본 것처럼 말하지 않는다.

메뉴·레이아웃은 사용자 요청에 따라 바꿀 수 있다. 6개 분석 기능은 기본으로 유지하되 이름·순서·위치는 아래 설정으로 덮어쓴다. 사용자가 기능 변경까지 명시한 경우 해당 범위도 반영한다.

- `menu_items`: 안정적인 기능 ID와 표시 이름을 가진 목록. 목록 순서가 메뉴 순서이다. ID는 overview/daily/placement/keyword/insights/actions를 사용한다.
- `navigation_desktop`, `navigation_mobile`: 메뉴 위치. 기본은 각각 top, horizontal이다. sidebar 등 요청한 배치로 변경할 수 있다.
- `kpi_order`: revenue/cost/roas/orders/ctr/cpc/cvr/cpa 표시 순서.
- `overview_layout`: 기본 split, 전체 너비 차트 요청은 chart_full_width 등 의미가 명확한 값으로 저장하고 구현한다.

위 값은 장식용 메모가 아니다. 매 실행 시 읽고 결과물에 적용한다. 복잡한 배치는 `reference.md`에 영역별 요구를 덧붙여 설명한다. 이전 기본 배치보다 사용자가 선택한 최신 설정을 우선한다.

수정은 기존 파일을 읽고 필요한 부분만 수행한다. 메뉴 수정은 이름·순서·대상 화면·선택 표시, 레이아웃 수정은 카드 순서·차트 크기·모바일 넘침·기존 상호작용을 확인한다. 같은 분석 조건의 합계가 수정 전후 일치해야 한다. 재생성 후에도 선택한 구성이 유지되는지 확인하고 검증 기록에 남긴다. 실제 광고 데이터와 설정 변경 요청 없이 예시 메뉴나 배치를 자동 적용하지 않는다.
